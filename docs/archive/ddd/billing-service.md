# Billing Service Design

## 1. Overview
The **Billing Service** manages user subscriptions, usage quotas, and payments. It implements a **Hybrid Billing Model** that supports both traditional Fiat payments (via Stripe) and Crypto Staking (Asset-backed usage credits).

## 2. Architecture

### 2.1 Hybrid Payment Model
The system supports two distinct paths for unlocking service tiers:

1.  **SaaS Subscription (Fiat/Stripe)**:
    -   Standard monthly recurring credit card payments.
    -   Managed via Stripe Customer Portal.
    -   Immediate quota unlock upon webhook verification.

2.  **Asset Staking (Crypto/Mudarabah)**:
    -   Users stake approved assets (BTC, ETH, BNB, USDT) into a smart contract or tracked wallet.
    -   **Islamic Finance Principle**: The user retains ownership of the asset. The "payment" is the *yield* or *utility* generated by the asset, which is shared with the platform in exchange for service credits.
    -   **Yield Calculation**: `Credit = StakedAmount * AssetPrice * YieldRate`.

### 2.2 Quota Management
Usage is strictly enforced via the `checkQuota(userId, tokensRequested)` function in `billing.ts`.

-   **Tiers**:
    -   **Free**: 10k tokens/mo.
    -   **Pro**: 1M tokens/mo (or $1000 FLX Stake).
    -   **Enterprise**: Unlimited (or $10k FLX Stake).
-   **Enforcement**:
    -   Pre-check before every AI Router request.
    -   Atomic decrements in `user_usage_quotas` table.

## 3. Data Schema

### 3.1 Subscriptions Table
Tracks the user's current status and method.
```sql
TABLE public.subscriptions (
    user_id UUID,
    tier ENUM('free', 'pro', 'enterprise'),
    payment_method ENUM('stripe', 'staking'),
    stripe_subscription_id TEXT,
    staking_details JSONB
);
```

### 3.2 Staked Assets Table
Tracks individual crypto assets contributing to the user's tier.
```sql
TABLE public.staked_assets (
    user_id UUID,
    asset_type TEXT, -- 'BTC', 'ETH'
    amount DECIMAL,
    entry_price_usd DECIMAL,
    is_active BOOLEAN
);
```

## 4. Key Workflows

### 4.1 Staking-to-Subscribe
1.  User transfers crypto to the Vault.
2.  `recordStakingEvent(userId, asset, amount)` is called.
3.  System calculates `calculateStakingFlxCredit(userId)`.
4.  If `Credit > TierThreshold`, `refreshSubscriptionFromStaking()` upgrades the user to Pro/Enterprise automatically.

### 4.2 Mining Rewards (Profit Sharing)
Miner rewards are distributed from the platform's profit pool.
-   **Mudarabah Pool**: 50% of platform profits are allocated to the Miner Pool.
-   **Distribution**: Proportional to the `resource_value_usd` provided by each miner.
