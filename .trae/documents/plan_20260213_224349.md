# Documentation Reorganization & SEO Enrichment Plan

I have analyzed the current documentation structure and content. My plan is to transform the `docs` directory into a professionally organized, SEO-optimized knowledge base.

## 📂 Proposed New Structure
I will reorganize the files into the following logical categories, standardizing all filenames to **kebab-case**:

- **`docs/core/`**: Fundamental system concepts.
  - `architecture.md`, `control-plane.md`, `security-model.md`
- **`docs/network/`**: Sovereign Network and P2P infrastructure.
  - `network-v2.md`, `p2p-principles.md`, `token-economy.md`, etc.
- **`docs/features/`**: Specific platform capabilities.
  - `agent-zero.md`, `auth-rbac.md`, `billing-staking.md`, `integrations.md`
- **`docs/api/`**: Technical interfaces and references.
  - `api-reference.md`, `protocol-specs.md`
- **`docs/reports/`**: Formal analysis and audit documents.
  - `security-audit-2026.md`, `ddd-requirements.md`, `architecture-patterns.md`
- **`docs/project/`**: Project management and tracking.
  - `roadmap.md`, `global-strategy.md`, `progress-tasks.md`

## 🔍 SEO Header Implementation
Every `.md` file will be enriched with a YAML frontmatter block for better indexing and metadata management:

```yaml
---
title: "Descriptive Page Title"
description: "A concise summary of the document content for search results."
keywords: ["flexai", "decentralized", "ai-infrastructure", ...]
category: "Core | Network | Features | API | Reports | Project"
last_updated: "2026-02-13"
---
```

## 🛠️ Implementation Steps

### 1. Structure Preparation
- Create the new categorical directories (`core`, `network`, `features`, `api`, `reports`, `project`).
- Merge redundant files (e.g., duplicate architecture docs).

### 2. Migration & Naming
- Move all markdown files to their respective folders.
- Rename files using consistent **kebab-case** (e.g., `auth_rbac.md` → `auth-rbac.md`).

### 3. SEO Content Injection
- Analyze each file's content to generate unique titles, descriptions, and keywords.
- Prepend the YAML frontmatter to each file.

### 4. Link Repair
- Update all internal markdown links (e.g., `[Docs](/docs/control-plane.md)`) to reflect the new directory paths.
